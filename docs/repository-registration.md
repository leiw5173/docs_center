# 文档团队接入填写指南

本指南适用于[文档仓库接入或调整表单](https://github.com/leiw5173/docs_center/issues/new?template=document-registration.yml)。正文仍由业务仓库维护，申请通过 Issue 进入登记 PR；登记合并不等于正文发布。

## 提交前准备

确认来源仓库地址、实际文档分支、已有的 `zh` / `en` 目录，以及希望展示的[目标分类](category-catalog.md)。来源应包含各目录的 `index.md`、有效的文档链接和排序信息。私有来源需要事先具备读取权限。

## 表单逐项填写

| 表单字段 | 去哪里找、如何填写 | 示例 |
| --- | --- | --- |
| 来源仓库 | 从业务仓库地址复制账户名和仓库名，格式为 `owner/repository`，不要带网址前缀 | `leiw5173/docs_test` |
| 分支 | 在业务仓库的分支选择器查看实际文档分支；新接入留空默认 `main`，若为 `master` 等需填写；已有来源留空沿用原分支 | `main` |
| 语言 | 按实际存在的文档目录选择；只维护中文时仅选 `zh` | `zh` |
| 目标分类 | 从下拉列表选择完整中文路径；不再分别填写栏目代码、子类 ID 和分类路径 | `应用案例 / 教学与实践` |
| 来源标识（可选） | 通常留空；新来源默认用仓库名，将句点等符号转成短横线。只有标识或默认前缀被占用时才另取一个唯一名称 | 默认 `docs_test`；冲突时可填 `teaching-docs-test` |

已经登记的仓库仍填写同一个来源仓库。系统会查找原登记，保留原标识、地址前缀和目录层级，不会重新按仓库名命名。原信息可在[来源登记](../document-center/registry.json)查看，通常无需手动抄写。

例如，已用于验收的 `leiw5173/docs_test` 继续保留 `maintenance-test`，不会改成 `docs_test`。

## 登记 ID 和路径前缀是不是重复

两者用途不同，但新接入不应重复填写：

- **登记 ID（来源标识）**标识某个文档来源，用于候选清单、引用关联和审核记录。
- **地址前缀**是读者文档地址的一部分。例如前缀为 `docs_test` 时，`zh/guide/steps.md` 的来源路径是 `docs_test/guide/steps.md`；语言由页面语言参数区分。

新来源默认让两者相同。已有来源允许不同，例如 `docs-courses` 的登记 ID 对应地址前缀 `courses`；`docs-buildroot` 对应 `software/SDK/buildroot`。这些历史地址必须保留，不能为了统一命名而自动改写。

因此，表单只保留一个可选的“来源标识”；地址前缀自动生成或沿用，不再要求团队重复输入。发生重名时系统会停止生成登记 PR，并提示填写另一个来源标识，不会覆盖其他仓库。

## 栏目、节点 ID 和分类路径在哪里

见[接入分类目录表](category-catalog.md)。文档团队只选一个中文目标分类，最多为“顶级栏目 / 直接子类”，如“操作系统 / Bianbu”，系统自动关联三个值。没有合适位置时先按该表的流程提交“分类新增或调整”反馈，由文档团队协调确认；反馈不会自动创建分类。

调整分类只改变展示归属，不自动改变文档地址。不同业务仓库的内部目录层次仍由各自的 `index.md` 和文档组织维护。

## 为什么不再填写 rootDep

`rootDep` 是兼容来源树的技术参数：将按地址前缀展开的来源树中某一层目录标记为根节点。它不表示网站分类的层数，也不是 `sidebar_position`。

新来源使用自动生成的单层前缀，默认值为 `1`。已有来源保留原值，包括历史上与前缀层数不同的配置；不会重新计算或“纠正”。分类移动也不修改此值。文档团队不需要填写它。

## 登记 PR 审核清单

1. 来源仓库、分支及语言正确，读取检查通过。
2. 目标分类符合内容归属；需要的目录已经存在且可用于所选发布语言。
3. 新来源标识唯一、地址前缀合理；已有来源的标识和地址前缀与原登记一致。
4. 登记 PR 只调整本次来源，没有遗漏或删除其他来源。
5. 文档团队确认后合并登记 PR，再审核生成的候选发布 PR。候选未确认发布前，阅读页不应变化。

## 遇到问题如何处理

| 提示或需求 | 处理方式 |
| --- | --- |
| 来源标识或默认地址前缀已占用 | 新来源填写另一个来源标识；不要修改其他仓库登记 |
| 找不到合适分类 | 提交“分类新增或调整”反馈，确认后更新分类目录表和表单 |
| 改名、替换来源仓库或迁移已有地址 | 提交单独迁移申请，说明旧值、新值、影响文档、引用和旧地址保留方案；普通接入表单不执行迁移 |
| 检查失败 | 查看 Actions 的具体错误，修正 Issue 字段或回业务仓库修正文档后重试；失败不等于已经登记或发布 |
| 接入登记完成 | 继续审核候选发布 PR；看到最终发布结果并核对网页后才算完成 |

已有旧版 Issue 仍可识别技术字段，以保留历史申请可重试性；但也不允许通过旧字段隐式更改已登记来源的标识、前缀或层级。
