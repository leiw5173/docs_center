# 文档维护与发布流程

本设计依据本次提供的流程图。治理配置和发布清单保存在 Git；正文继续在业务仓库维护。以下机制是本次开发内容，不代表已接入生产。

## 主链路

新来源：提交接入 Issue → 一个接入 PR（来源登记及各语言首版固定清单）→ 接入检查 → 内容检查与预览 → 文档团队确认合并一次 → 登记与首版发布统一执行。预览无需先登记；任一语言或来源发布失败，登记与本轮全部首版内容一起回滚；不再派发独立的首轮候选 PR。

已接入来源的日常更新按以下链路维护：

1. 在业务仓库修改 Markdown、各目录的 `index.md` 和 `sidebar_position`，按业务规则合并 PR。
2. 已验签的业务 Webhook 只向治理仓库发送候选事件，不再直接改线上目录或正文。事件必须包含注册仓库、完整提交 SHA 和 PR 号。
3. 治理自动流程以仓库为最小发布单位，根据文档直接、间接引用计算关联组，按固定 SHA 创建或更新该组的候选发布 PR。同一次变更涉及中英文时，一个候选 PR 包含两份发布清单，中英文分别检查和预览，团队合并一次。未关联仓库独立审核；删除引用的这一轮，按上一已确认关系与候选关系的并集成组，避免提前拆开。正文不复制到治理 Git。
4. 发布 PR CI 重新读取固定 SHA，检查正文、资源、目录、引用、地址、版本等。通过后将清单交给独立后端，由后端获取固定正文/资源、使用正式渲染器生成隔离静态预览 Artifact。检查报告区分阻断错误和人工核对项。缺英文只提醒，不阻断中文。
5. 文档团队在 PR 中核对预览、反馈、标签、地址迁移与版本归档，手动合并。必须把 CI 检查设为分支保护必需项，禁止机器人批准/合并。
6. 合并后的受保护工作流向后端发送清单；后端重新拉取固定正文、比对哈希，在同一个数据库事务中切换本 PR 的全部仓库和语言。失败则保留之前完整目录和正文。

## 配置与输入

`document-center/registry.json` 登记来源、语言、目标栏目和路径前缀。维护人员按[接入填写指南](repository-registration.md)提交 Issue，由自动流程生成接入 PR，文档团队核对登记及首版内容后合并。来源标识、地址前缀和兼容目录层级在新接入时自动生成，调整已有来源时沿用原值，不通过普通接入隐式迁移。

接入表单只选择一个中文“目标分类”，按[分类目录表](category-catalog.md)关联栏目、子类节点 ID 和完整路径。分类登记保存在 `document-center/categories.json`，分类新增或调整先由文档团队通过反馈协调确认；修改分类登记不等于自动创建网站目录。旧版 Issue 的技术字段继续兼容，但不得借此改写已有身份或地址。

每个发布 PR 提交 `document-center/releases/<language>/<groupId>.json`，包含来源固定 SHA、逐文件 SHA-256、引用、标题、排序、版本、资源哈希和人工确认清单。静态 HTML/正文只存 CI Artifact 或执行方存储，不提交到治理仓库。

## 发布检查

| 类别 | 自动检查 | 文档团队核对 |
| --- | --- | --- |
| 页内/文档链接 | Markdown AST 提取普通、引用式链接和图片；目标文件、锚点、资源存在 | 外部网站和跨仓库链接登记 |
| 内容完整性及序号 | 空正文或缺 H1 阻断。新增或改动的正文只有修订记录，或概述、安装、操作步骤等关键章节为空时阻断。普通空章节、历史未改动问题、占位文字和列表序号进入人工核对 | 明显缺章、内容是否完整，列表是否应连续编号 |
| 标题数字 | 正文标题和 front matter 标题以 `6.1` 等章节编号开头时提醒 | 是否需要去掉编号 |
| 版本归档 | 列出新增、修改、删除文档及前后 `software_version`，未声明或版本未变也进入核对清单 | 是否升级版本、旧版归档是否就绪；不会自动升级或归档 |
| 中英文 | 另一语言缺失时提醒。已有对应文件却只修改一种语言时阻断，直至同步修改或文档团队开 Issue 说明接受差异的原因 | 根据 PR 评论链接填写原因并提交 Issue，再重跑检查。Issue 绑定该 PR 和本次差异，候选内容变化时重新核对 |
| 目录介绍 | 每个含 Markdown 的目录须有 `index.md`。发布从语言根目录的 `index.md` 出发，只展示经各级目录索引的相对链接声明的正文。新增或修改的 `index.md` 缺少介绍段落时阻断，已发布且本轮未改动的文件缺少介绍时提醒 | 在标题下写一段本目录覆盖的主题、适用任务或阅读顺序。文档中心从目录入口展示这段内容，评审时核对介绍是否准确 |
| 地址变更与旧链接跳转 | 自动登记可确定的迁移，测试网页部署后用浏览器打开旧链接并验证最终页面，跳转失败时阻断并列出经过的地址 | 在 PR 评论打开旧链接、预期新地址和受影响的引用文档，核对原链接附近的内容。有歧义时选择迁移目标 |

内容检查的工作流摘要逐项展示检查结果，预览 Artifact 中的 `index.html`、`report.md` 和 `report.json` 保留明细。中英文各有一份报告。首次接入没有历史基线，不能据此认定历史引用、版本和地址无需处理。零自动发现不代表人工审核通过。

`sidebar_position` 用于目录排序，不等同于正文有序列表必须从 1 开始。

目录或文档迁移后，候选 PR 自动列出“旧路径 → 新路径”，CI 同时显示地址变更告警。通常无需填写治理表单；合并发布后，读者打开旧文档或旧目录书签，会自动跳转到当前有效地址，并保留语言和页内定位。再次迁移仍保留最早旧链接。无法唯一识别迁移、目标不存在或重定向成环时禁止发布；PR 提供已填好的目标选择链接，核对后提交即可。单纯删除文档也必须先安排有效去向，不能静默留下失效链接。显式指定历史发布版本的链接继续保持固定版本。

## 发布隔离与并发

候选只更新 PR。预览不改正式数据库、CDN 或 RAGFlow。候选的检查结果绑定清单哈希和提交 SHA；后端只接受逐文件哈希匹配的固定内容。重复发布相同清单幂等；并发清单通过数据库锁串行化。

业务新提交替换未合并候选；已合并的清单冻结，后续修改进入下一轮。旧事件必须做 Git 祖先关系检查，禁止较旧提交覆盖新候选。发布事务失败自动回滚；页面不可达、渲染失败、线上清单不一致的上线后回滚仍需部署执行方提供可验证的探测和上一完整版本恢复接口，不能把数据库事务回滚说成上线回滚。

来源通知按仓库保留独立运行；同一来源的新通知作为唤醒，读取当前分支头并锁定 SHA。同组候选更新时检查历史不能倒退或分叉，按关联范围加载来源，不因接入一个新仓库而抓取全部未关联来源。清单与 `document-center/state/<language>/<repoId>.json` 修订指针在同一 Git 提交中更新；关联组变化时生成替代 PR 并关闭过期候选。并发更新使用版本校验，禁止覆盖已经推进的候选。

## 启用条件

- 独立私有治理仓库，只有文档团队可见内部检查。
- GitHub App/专用 token：治理 contents/PR 写权限；业务源只读。发布 secret 仅用于受保护环境，业务仓库不持有。
- 配置真实 registry、治理仓库、治理 Webhook、受保护分支和发布环境。
- 现有本地管理发布入口在治理模式关闭；紧急人工发布必须显式使用 legacy 模式，不可把业务 Webhook 绕回直发。
- 本地可验证自动检查、候选清单、静态预览、事务式发布和幂等；真实 PR、私有预览权限、线上探测及完整回滚须在接入环境验收。

## 子类与结果回报

登记可携带 `parentNavigationId` 或 `navigationPath`，候选清单完整保留这些信息。目标分类需位于所选顶级栏目中；不存在或有歧义的子类拒绝执行。重复发布复用该位置，既有逐文档跨栏目入口继续保留。

检查和预览状态回写到同一 PR，并绑定候选 head SHA；旧检查任务不能覆盖新修订状态。CI 请求执行方在独立环境运行同一套发布逻辑，以文档中心实际前端展示候选发布后的栏目、目录、侧栏、面包屑和正文。确认完整应用可访问、候选 API 与固定来源修订一致、旧链接可解析到新地址后，在 PR 评论给出“文档中心预期效果”和“测试旧链接自动跳转”入口。独立正文 HTML、ZIP 附件不能代替文档中心测试部署。测试站与已发布数据隔离，页面标识“尚未发布”，各候选的预览上下文在导航和刷新时保留。

预览评论逐条列出相对上一已确认清单发生变化的页面，标注新增、修改或迁移，并直接打开对应正文；初次接入列出全部可展示的首版正文。目录用的 `index.md`、`readme.md` 不作为独立正文链接或旧址测试入口，但继续保留在来源、目录构建和迁移清单中。未变化的关联文档不列入清单，目录位置、标签或引用变化涉及的普通正文仍需列出。页面较多时分条评论完整展示，不以文档中心首页替代变更页面入口。

发布受理后，最终回报等待本组所有已配置同步任务完成；部分成功仍是发布中，失败明确回报，可修复重试。结果及回报状态持久化，发送中断重试时更新同一结果评论，不重复发布。未启用外部同步的本地模式明确回报本地发布完成。

注册与业务合并的测试步骤见 [两类测试清单](maintenance-acceptance.md)，已完成的真实测试见[验收记录](maintenance-acceptance-results.md)。后续来源仍需按实际环境验收，本地模拟结果不能代替真实测试。
