# 新业务仓库的两类测试

本清单用于测试环境验收。代码、本地模拟和单元测试通过，不等于这两类真实测试已执行；新仓库由维护人员创建后再填写实际链接和结果。

## 准备测试仓库

将 [测试文档样例](../examples/business-repository) 中的 `zh` 目录复制到新业务仓库根目录，提交到默认分支。样例包含目录介绍、排序、正文、页内锚点和本地图片，内容明确标记为维护流程测试。

首次接入申请按[接入填写指南](repository-registration.md)填写；旧验收 Issue 的技术字段保留为历史记录，新表单不再要求重复填写。

| 字段 | 测试值 |
| --- | --- |
| 来源仓库 | 实际的 `owner/repository` |
| 分支 | 实际默认分支，通常为 `main` |
| 语言 | `zh` |
| 目标分类 | 选择 `应用案例 / 教学与实践` |
| 来源标识（可选） | 通常留空；需独立测试名称时填写 `maintenance-test`，新地址前缀随之生成 |

栏目、子类 ID、分类路径、地址前缀和目录层级由系统关联或沿用。已登记的 `leiw5173/docs_test` 自动保留现有标识和前缀 `maintenance-test`。新测试仓库使用其他标识时，下文的来源路径也以登记 PR 生成的值为准。

开始前确认：测试仓库可被流水线读取；测试环境中已有目标分类；维护人员权限、检查、预览和结果回报已接通。私有来源应先具备所需的只读访问。测试来源的所属账户/组织需与测试执行环境的来源设置一致。登记和发布都以具体 PR 为准，不用直接编辑配置文件。

## A. 新仓库接入并首次发布

1. 提交“文档仓库接入或调整”Issue，得到一个接入 PR，其中同时包含来源登记和各语言的首版固定清单。
2. 第一阶段 CI 检查所选仓库、分支、语言及分类；不因接入一个来源去检查所有无关来源。
3. 第一阶段通过后，第二阶段 CI 检查首版正文、目录、图片和链接，并生成各语言预览。只有中文时只检查中文；中英文都有时两个语言都必须有首版清单，锁定同一来源提交。
4. 从文档团队飞书通知打开预览，核对内容和“应用案例 → 教学与实践”的位置。接入 PR 未合并前，新来源不登记到执行环境，阅读页不增加本轮文档。修正文档后编辑原接入 Issue 重新生成同一个 PR，不需要另建首轮候选。
5. 文档团队确认后只合并这一个 PR。登记与首版发布统一执行，任一部分失败不应只留下已登记或部分语言已发布的状态。
6. 查看该 PR 的最终发布回报，再核对测试站正文、图片与分类。未启用外部同步的测试环境明确回报“本地发布完成”；受理不等于完成。
7. 重试相同接入请求，不重复创建目录、发布任务或最终结果评论，也不再生成第二个首轮候选 PR。

跨仓库引用、标签或迁移信息仍可通过治理 Issue 补充到同一个待审核接入 PR，更新后重新检查。有关联来源正在其他 PR 中待确认时，先协调处理重叠候选，不能并行确认两份冲突版本。

记录：接入 Issue、同一个接入 PR、来源 SHA、预览通知、最终回报和实际结果。

## B. 业务 PR 合并触发更新

1. 在业务仓库新建分支，将 `zh/guide/steps.md` 的 `REGISTER-V1` 改为 `MERGE-V2`，提交业务 PR。
2. 业务 PR 未合并时，测试站保持 `REGISTER-V1`。
3. 合并业务 PR，确认生成或更新对应引用关联组的候选发布 PR，清单锁定具体 SHA。候选尚未合并时，测试站仍保持上一版。
4. 在同组候选 PR 未合并时，再合并一次业务修订；应更新同一个发布 PR，并对新修订重新检查，旧修订的检查不得放行新内容。
5. 加入一个不存在的 Markdown 链接并合并业务修订：候选应检查失败，PR 回报失败位置与检查入口，不能正式发布。修复链接再合并，应继续更新该候选 PR 并重新检查。
6. 文档团队从飞书通知打开预览，检查后手动合并候选，等待最终结果。测试站应显示最新已确认标记，仍位于原子类，且没有重复目录。
7. 重复投递同一合并事件或重试执行，不应重复建发布 PR、重复目录或重复结果评论。旧任务不得覆盖新修订的状态。

若需要验证真实跨仓库关联，再加入一个可读、已登记的测试来源：A 引用 B，B 引用 C 时应同组；未关联 D 保持独立。关联组扩大时替换旧候选，保留关闭说明，不能继续合并过期候选。

## 结果判断

| 观察结果 | 判断 |
| --- | --- |
| 只增加了登记文件 | 仅登记完成，不算发布通过 |
| 只生成了候选 PR 或预览包 | 尚待人工确认 |
| 执行请求已受理 | 还需查看最终回报 |
| 工作流超时或中断 | 状态待核对，不能推断已回滚 |
| 同步失败 | 保留失败结果，修复后重试并更新同一结果评论 |
| 回报发送失败 | 发布结果保留并重试回报，不重复执行发布 |
| 最终回报通过且测试站内容、目录、资源一致 | 对应测试用例通过 |

本轮测试不把数据库事务回滚等同于完整部署回滚；整站探测及恢复上一完整版本的验收另行进行。
